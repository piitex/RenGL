# Vulkan and the optional 3D layer: status

A working document, not API documentation. It records what has been built for the Vulkan backend and the 3D layer,
what is known to be wrong or missing, and what comes next. Last updated 2026-10-04. The API itself is documented in
[3D](3d/README.md) and [Rendering APIs](core/rendering-apis.md).

## Goals and decisions

| Decision | Detail |
|---|---|
| Vulkan for the 2D UI | Skiko 0.999.0-SNAPSHOT (a local build of JetBrains/skiko#1201) draws the UI through Vulkan. Pick it with `WindowOptions.setRenderer(RenderAPI.VULKAN)`. |
| 3D is optional | Basic apps and 2D games must not pay for it: no 3D initialisation, no cost when unused, no 3D types in `Window` or `Element`. The `render3d` package is only touched by code that asks for it. |
| Both OpenGL and Vulkan | The 3D layer runs on whichever API the window uses. The same GLSL source and the same scene code run on both. |
| Both presentation modes | An embedded `Viewport3D` element and whole-window 3D behind the UI (`Background3D`). Both done. |
| macOS OpenGL fatal error | **Done.** `RenderAPI.resolve` throws `IllegalStateException` (and logs fatal) when OpenGL is asked for on macOS, telling the developer to use `RenderAPI.VULKAN`. |

## What exists

### Vulkan backend for the UI

- `VulkanContext` owns the instance, device, queue and swapchain. `VulkanSkikoRenderer` draws Skia into the swapchain
  image each frame. Skia leaves the image in `COLOR_ATTACHMENT_OPTIMAL`; `endFrame()` moves it to the present layout.
- `RenderAPI` (`AUTO`, `OPENGL`, `METAL`, `VULKAN`). If the Skiko jar has no `makeVulkan`, the engine logs a warning and
  falls back instead of crashing with `NoSuchMethodError`.
- macOS runs Vulkan through MoltenVK. Metal's "primitive restart" warnings are silenced through `VK_EXT_layer_settings`.

### `GpuInterop` (the only core hook the 3D layer needs)

`gl.renderer.GpuInterop` gives GPU code what it needs to share Skia's context: `gpuApi()`, `skiaContext()`,
`vulkanContext()`, `pixelScale()` and `onDispose(Runnable)`. Only `SkikoRenderer` (OpenGL) and `VulkanSkikoRenderer`
implement it. Metal and the CPU snapshot renderer do not, so a `Viewport3D` there warns once and draws nothing.

### GPU abstraction (`render3d`, `render3d.gl`, `render3d.vk`)

- Interfaces: `GpuDevice`, `GpuBuffer`, `GpuTexture`, `Pipeline` and `PipelineDesc`, `RenderTarget`, `RenderPass`,
  `VertexLayout`, `ShaderCompiler`. Implemented by `GlDevice` (GL 3.3 core) and `VkGpuDevice` (Vulkan 1.1, VMA, a frame ring of 2).
- **MSAA:** `createRenderTarget(w, h, depth, samples)` and `maxSamples()` (1 to 8). A multisampled target keeps a single-sample
  colour image that the pass resolves into, so Skia, `readPixels` and everything else still see one sample per pixel. On Vulkan
  the render pass has a resolve attachment (render passes are made per sample count and depth) and pipelines are built per
  render pass, so `PipelineDesc` has no sample count. On GL a second framebuffer holds multisampled renderbuffers and `end()`
  blits them into the texture's framebuffer. `Viewport3D` and `Background3D` default to 4 samples (`setSamples`).
- **Mipmaps:** `createTexture(w, h, rgba, mipmaps)`. Vulkan blits level to level (`vkCmdBlitImage`) and falls back to no mips if the
  format can't blit; GL uses `glGenerateMipmap`. The scene layer turns them on for material textures. **Anisotropic filtering** is on
  at 8x (or the GPU's limit; `rengl.3d.anisotropy` overrides): a Vulkan sampler feature that `VulkanContext` already enables, and
  `GL_EXT_texture_filter_anisotropic` on GL. `maxAnisotropy()` reports it.
- **Instancing:** `VertexLayout.Rate.INSTANCE`, extra vertex buffers (`PipelineDesc.extraLayouts`, `bindVertexBuffer(binding, buffer)`)
  and `draw`/`drawIndexed(count, instances, firstInstance)`. Vulkan has this natively; GL 3.3 has no base instance, so the pass
  moves the instance attribute pointers `firstInstance` elements in at each draw.
- **Cube textures** (`createCubeTexture`) and **sampled render targets** (`createSampledTarget`, `RenderTarget.texture()`). A sampled
  Vulkan target uses its own render pass that leaves the colour in `SHADER_READ_ONLY_OPTIMAL`; its texture uses a clamped nearest or
  linear sampler. The scene's shadow map is one, with depth packed into the colour channels.
- **Vulkan frame machinery:** uploads made in a frame are recorded into one command buffer that is submitted ahead of the next pass (no
  `vkQueueWaitIdle` per mesh); descriptor pools grow when full, so there is no draw ceiling; a dynamic buffer whose frame slot missed
  an update is brought up to date from the slot that has the latest data before it is read.
- `PipelineDesc.frontClockwise` (the scene uses it for mirrored nodes). The 6-argument constructor still exists.
- Shaders are one GLSL 450 source. shaderc compiles it to SPIR-V for Vulkan. SPIRV-Cross turns the same SPIR-V into GLSL 330 for GL.
- Conventions the code relies on: clip space is +Y up with depth 0..1 on both backends. GL targets have a bottom-left origin (`isBottomLeftOrigin()`), Vulkan ones top-left. `readPixels()` returns the top row first.
- `Gpu3D` (package-private) makes one `GpuDevice` per window on the first draw of any viewport, and closes it when the window's renderer is disposed.

### `Viewport3D`

- An `Element` that is `Focusable`, `Draggable` and `Scrollable`. A `Content` renders into an offscreen target at
  `width * pixelScale * resolutionScale`. The target is wrapped as a Skia render target, snapshotted, and drawn like an image.
- An optional `InputListener` receives pointer, drag, scroll, key and focus events. Only the left button drags.
- A `Content` can be shared by several viewports.
- `InputListener.clicked(x, y)` fires after `dragEnded` when the mouse never left a 4 point radius of the press. `Background3D` does the same from the game `Input`.

### Scene layer (`render3d.scene`, `render3d.math`)

- **Picking:** `Camera.screenRay`, `Scene3D.pick(x, y, w, h)`, `pick(Ray)`, `pickAll(Ray)`, `Node3D.setPickable`. A box test in scene space, then a per-mesh BVH (built on first pick, median split on centroids, leaves of up to 4 triangles) with Moller-Trumbore in the mesh's own space (so non-uniform scale works). Instanced nodes are tested per instance (`Hit.instance()`); skinned meshes are posed on the CPU and searched without a stored BVH. Back faces are skipped unless the material is double-sided, matching what is drawn.
- `Scene3D` (root `Node3D`, `Camera`, up to 8 lights, ambient, background colour or `Skybox`, shadow settings, animation players, update handler), `Node3D` (TRS, children, mesh and material, instances, skin, shadow flags), `Mesh` (cube, sphere, plane, computed normals, optional skinning data), `Material` (classic: colour, texture, specular, shininess; PBR: metallic, roughness, normal, metallic-roughness, occlusion and emissive maps; unlit, double-sided, blend, alpha cutoff), `Light` (directional, point, spot; up to 4 lights cast shadows, each with its own `Shadows` settings and `LightFalloff`), `Skybox` (gradient, cube, equirect), `Instances`, `Skin`, `AnimationClip`, `AnimationPlayer`, `OrbitControls`.
- `Model.load` reads glTF, GLB, OBJ, FBX and Collada through LWJGL Assimp. It is CPU only, so it is safe on a background thread. glTF materials load as PBR with their maps; bones become a `Skin` and `Mesh.setSkinning` data (4 bones a vertex, 256 a mesh); animations become `AnimationClip`s (`Model.animations()`, `Model.player()`).
- `SceneRenderer` (one per device): a forward renderer. Each frame it collects the visible nodes, sorts the opaque ones by pipeline, material and mesh, and writes one 176-byte record per node or instance into an instance-rate vertex buffer (model matrix, normal matrix, tint, material parameters, flags); adjacent draws with the same mesh and material merge into one instanced call. One shader pair covers classic Blinn-Phong, PBR (GGX, Smith, Schlick) and unlit, chosen per record, with normal mapping from an exact tangent solve. PBR ambient is a diffuse plus a rough specular term, or, with `setEnvironmentLighting`, the sky's: nine SH coefficients (computed once on the CPU by `Environment`) for diffuse and the sky's own mipmaps for reflections, with the split-sum BRDF fitted analytically; that is a fragment-shader variant per sky kind (gradient, cube, equirect) through `#define ENV_KIND`, bound at texture binding 8. Nodes wholly outside the view are culled by a sphere test against the six frustum planes (an instanced node by one sphere around all its copies) unless they cast shadows, in which case they only draw into the shadow map. A morphed node is blended in the vertex shader from a texture of the mesh's shape offsets (binding 9) and a block of up to 16 shapes in use and their weights (binding 10), in the main and shadow programs; more than 16 shapes on, or a huge mesh, falls back to a dynamic vertex buffer of its own, refilled on the CPU when its weights change. Shadow-casting lights add one depth pass first into a shared atlas (`ShadowAtlas`, one sampled RGBA8 target with packed depth, shelf-packed square tiles, shrunk to fit `setShadowAtlasSize`). `ShadowPlanner` (plain maths) picks up to 4 lights (directional first, then nearest) and makes their views: per directional cascade an orthographic fit around a bounding sphere of the camera's frustum slice (practical split, snapped to texels), one perspective view for a spot light, six faces of about 92 degrees for a point light (the shader picks the face by the major axis). Each view draws into its tile through `RenderPass.setViewport` with its own pooled uniform buffer, and casters are sphere-culled per view. The lookup applies a normal offset and a slope-scaled bias and filters with a built-in or custom `ShadowFilter`; the scene fragment shader is generated from the set of custom filter and falloff snippets in use, one program per set (the pipeline key carries the set's index). The skybox draws as a full-screen triangle. Per-render-call resource sets (frame block, instance buffer, joint buffers) stop a scene shown in two viewports from overwriting its own data within a frame. Mesh and texture caches are evicted after 600 undrawn frames.

### Physics (`render3d.physics`)

- Own pure-Java engine, documented in [Physics](3d/physics.md). `Scene3D.setPhysics(world)` runs `PhysicsWorld.update(delta)` once per frame after the animators and before the update handler; a scene without one pays nothing.
- `RigidBody` keeps its state as floats (centre of mass, orientation, velocities) for the solver and exposes `Vec3`/`Quat`. Inertia is a full 3x3 tensor in the body's frame built from the shapes (parallel axis for offsets and turned shapes), turned into world space each step; locked axes zero rows of it. Integration is semi-implicit Euler with quaternion spin; gyroscopic terms are left out.
- A body follows its `Node3D`: it reads the node's world transform when added (scale bakes into the shapes), writes position and rotation back through the parent's inverse, and teleports when the node is moved by other code (detected by comparing with what it last wrote).
- Fixed step (1/60 s) with an accumulator, a cap of 8 steps per update, and interpolation between the last two steps.
- `BodyTree`: a dynamic AABB tree (Box2D's layout: surface-area insertion cost, AVL rotations) whose leaves are each body's box grown by 10 cm and stretched by four steps of its motion; a leaf moves only when its body leaves it, or has stopped inside a far bigger one. Planes, being endless, sit beside it and every query sees them. Raycasts, overlaps and the character's queries ask it, and take its answers in the order the bodies were added, so results don't depend on the tree's shape. Static, sleeping and still kinematic bodies aren't re-placed each step (their shapes would come out the same); moving one by hand places it then and there. With 20,000 static boxes and 200 crates a step went from 6.2 ms to 0.68 ms and a raycast from 72 µs to under 1 µs.
- Broadphase: each moving (or kinematic) body asks the tree what its box reaches; two moving bodies are paired by the one with the lower id. Narrowphase: per-pair tests (box-box SAT with face clipping and edge contacts, capsule-box by golden-section search on the convex signed distance plus a face clip for lying capsules, SAT fallback for deep overlaps), manifolds of up to 4 points: the deepest, then the widest spread around it (ties of depth go by position so the choice doesn't flicker), near-duplicates merged; a full manifold of 16 swaps out its shallowest point.
- Hulls: quickhull with a conflict walk across edges and coplanar triangles merged into polygons (compared with the seed face so curves don't merge into one bent face). Mass properties from tetrahedra (Blow and Binstock), so a hull's centre of mass and full inertia tensor (products included) feed the body's. A hull isn't recentred: it stays where its points are, like the mesh it came from. Scaling rebuilds the hull from scaled corners (exact for any scale) and the last result is kept.
- Hull contacts: polytope against polytope by SAT over both polytopes' face normals and every pair of merged edge directions (exact projections, no Gauss-map pruning yet), faces preferred unless an edge is clearly better, then face clipping or the closest points of the two support edges. Spheres and capsules use GJK (subset search over the simplex in doubles) from their middle line to the polytope, a face clip for a capsule lying flat, and SAT for a middle line that crosses the polytope.
- Meshes: corners joined by exact position; each triangle edge is real (border, shared by three or more, or folding outward by more than about 5°) or a seam. A median-split tree over the triangles serves contacts (box overlap in the mesh's space) and rays (two-sided Moller-Trumbore). Each touched triangle is tested as a two-sided flat polytope; a contact at a seam (by the feature GJK or the support corners give) is turned to the triangle's face normal, on the side the other shape's middle is on. Triangle contacts with normals within about 2° merge into one manifold named by the lowest triangle, so a box on a flat mesh has one contact of 4 points, as on a plane.
- `BodyShape.scaled` takes each axis's sign from the node axis it lies along, so turning a non-uniform scale into a turned shape's frame no longer mirrors it (a no-op for the round shapes, but a hull would have been flipped).
- Solver: sequential impulses with warm starting (points matched in body A's space, friction carried as a world vector), circular Coulomb friction, restitution after the velocity passes (with a pseudo-velocity fix so a speculative bounce happens at the surface), split-impulse position correction (slop 2 mm, 20 % a step), speculative contacts sized by speed, and passes that alternate direction. Island sleeping by union-find over contacts; sleeping bodies keep their contacts so a hit wakes the whole stack.
- Queries go through the `BodyTree`; a mesh body's triangles are found through its own tree. Events are per body pair, after each step.
- `ColliderView`: a node of see-through meshes, one per shape, built by `ColliderMeshes` (boxes, lat-long spheres and capsules pushed out so their flat faces circumscribe the shape, hull faces, mesh triangles, a 100 m square for a plane), each a few millimetres outside the shape. The renderer only draws triangles, so the edges are a repeating texture of lines at whole texture coordinates, and each face's coordinates run to a whole number of about one per metre: lines on the edges and across big faces at a steady width, continuous across the triangles of a face. Squares for boxes, spheres, capsules and planes; a triangle pattern (with diagonals) for hulls and meshes. One material per pattern and state (awake, asleep, kinematic, static, trigger, character), unlit and blended. Contacts and joints are pooled dots and stretched cubes. It syncs from `PhysicsWorld.writeNodes` with the same interpolation as the nodes, places itself under a moved parent correctly, and skips everything while hidden.
- Joints: sequential impulses inside the same velocity passes as the contacts (joints first, so contacts have the last word), warm started, then a non-linear position pass after integration (Box2D style, each joint's error fixed with its current mass, clamped to 0.2 m and 8° a pass, twice the contact position iterations, stopping early). Point joints solve a 3x3 block; a hinge's two alignment rows a 2x2 block; locks of all three angles a 3x3 block. A hinge's motor and stops act around the pivot, with the pivot's push folded into their mass (solved apart, a slammed door bounced off its stop). Springs are soft constraints (Catto's soft step) from a frequency and damping ratio. A body held to the world is the solver's body B, with a static stand-in for the world as A, so angles and reaction forces are the body's own. Joined bodies don't collide unless asked, share sleep islands, and wake with a moving kinematic partner.
- Scene files (`render3d.scene.file`): a node's body settings (`BodyKind`, `ColliderKind`, sizes, mass, friction, bounce, damping, gravity scale, sleep, trigger, layers, character size, mass, slope and step) are node properties in `SceneKinds` ("Physics", "Collider", "Character" groups), kept in `ScenePhysics` beside the node like `SceneMeta`'s notes; gravity and solver passes are world properties; joints are `SceneJoint`s with a property list per `JointKind`, saved as a `joints` array that names nodes. `Scene3DFile.load` (running) builds the world with `buildPhysics` and gives it to the scene if it has any body; an editor load builds none. An Auto collider fits what the node draws (a plane as a 2 cm box under it, a model as its triangles or, if dynamic, a hull), from the node's own mesh and its model only, never its children. A body or joint that can't be made is logged and left out, so a scene with a mistake still loads. `findBody`, `findCharacter` and `findJoint` look parts up by name.
- Character controller: a kinematic capsule body moved once per step before collision detection. The move is cut into pieces of half the radius; after each piece the capsule is pushed out of the deepest overlap (narrowphase, or the mesh path) up to 8 times, and the velocity and the rest of the move lose what pushed against. Walking, walkable ground lifts straight up (keeping the speed across a slope) and steep ground pushes straight sideways (so it can't be climbed); in the air the true normal is used, so a steep slope is slid down. Steps: lift by the step height, move across, drop; kept only if it got further and stands no higher than the step. Ground: walkable contacts under the round bottom within 5 cm; a slanted contact counts when a short ray just past it finds walkable ground (the edge of a step or ledge); the gap is closed, and a character grounded last step drops up to the step height to stay on stairs and slopes. Platforms carry it by their velocity at the feet, moved after the walk with the platform itself ignored. The body's velocity is set to cover the move, so the solver sees it moving. Loose bodies it walks into get a sideways impulse as an inelastic knock with its mass; one it stands on gets its weight, and their contact with it isn't solved (solved, the kinematic body held a rope bridge's planks down as if infinitely heavy, and the bridge sank under it).

### `Background3D` (whole-window 3D)

- A `Background` (the existing window-background hook), so `Window` and the engine loop did not change:
  `window.setBackground(new Background3D(window, scene))`. It wraps a full-window `Viewport3D`, so it renders the same way
  (offscreen target at window size times `pixelScale`, drawn by Skia as an image) and takes the same `Content`, which means a scene works in a viewport or behind the window.
- Engine order is clear, window background (the 3D), then every container, so the UI always draws over it.
- Input comes from the window's game `Input`, i.e. what the UI did not take: a press on empty space or on a panel with no click listener drags the
  listener (left button), the wheel scrolls, mouse movement and unhandled keys are forwarded. Buttons, sliders and text fields keep their own clicks.
- `setEnabled(false)` hides it and stops rendering. `setResolutionScale`, `setContent`, `setInputListener`, `close()`.
- Demo: `me.piitex.examples.demo.Background3DDemo`.

### Demo

`me.piitex.examples.demo.PhysicsDemo`: crates in a pyramid and a tower, a ramp, click to shoot a ball, a raycast showing what is under the mouse, and check boxes for pause, an icy floor, bouncy balls, low gravity and showing the colliders.

`me.piitex.examples.demo.DominoDemo`: 35 dominoes along an S-curve that fall end to end; push the first with a button or click any domino, and a check box for slow motion (the update handler feeds the world a quarter of the frame time).

`me.piitex.examples.demo.TerrainDemo`: rocks (hulls around random points, drawn with `toMesh`) and crates tumbling over a 7200-triangle terrain that is both the drawn mesh and a `MeshShape`; buttons drop rocks or crates, a click drops a rock where it lands, slow motion, and showing the colliders.

`me.piitex.examples.demo.PlaygroundDemo`: a character walked with WASD (relative to the camera), Shift and Space, followed by an orbit camera, over stairs to a tower, across a rope bridge of 12 hinged planks, down a ramp, up a gentle ramp and against a steep one, on a lift and a shuttling platform, through a hinged door, onto a seesaw, past pushable crates and a 2000 kg one, a pad that lights up through a trigger, and a wrecking ball on a rope that scatters a crate stack and knocks the character back. C rebuilds the crates, R resets, V shows the colliders.

`me.piitex.examples.demo.Scene3DDemo`: a main viewport (floor, textured cube, specular sphere, glass sphere, loaded model, orbiting point light),
a second small viewport with its own scene, sliders and check boxes for the lights, spin and glass, and a file dialog to load a model.
Run it with `-XstartOnFirstThread` on macOS. `-Drengl.demo.api=VULKAN|OPENGL` overrides the API (default Vulkan on macOS, OpenGL elsewhere; OPENGL on macOS is now the fatal error).

## Known issues and limits

### Correctness and robustness

1. Fixed in this stage: the primary window's renderer was never released at exit; every window's renderer, and with it
   `Content.dispose` and the 3D device, is now released when the engine stops (the validation layer is clean at teardown).
2. Fixed on Vulkan: uploads wait on the GPU per mesh. They are now recorded into the frame and submitted ahead of the next pass. GL
   uploads are the driver's.
3. Fixed on Vulkan: a frame that skipped a dynamic buffer's `update()` saw two-frames-old data. It now sees the latest.
4. Fixed: the Vulkan descriptor pools capped a frame at about 1000 draws. They grow, and the scene needs far fewer sets because
   draws that share a material merge.
5. 32-bit indices only, 16 vertex attributes at most, no push constants.
6. A `Viewport3D` and a `Background3D` re-render every frame by default. `setContinuous(false)` draws only on request, but the content must call `requestRender()` after changing a scene from code (input to the listener counts as a request). An animation player advances only when the viewport draws.
7. Fixed: the `rengl.vulkan.dump` aid left the swapchain image as a transfer source, which the closing barrier didn't expect, so the validation layer reported a layout error. The barrier now starts from the layout the image is in.
8. Found and fixed in this stage: `TextureData.decode` copied the decoded pixels with a relative `ByteBuffer.get`, which moved the buffer position, so `stbi_image_free` (which frees `address + position`) freed the wrong pointer and corrupted LWJGL's heap. Any model with embedded textures, or a few images in a row, crashed the JVM. Absolute `get(0, bytes)` fixes it. Window icons were not affected.
9. Found and fixed in this stage: a scene shown by two viewports wrote its frame uniform data twice in one frame into the same buffer, so the first viewport could draw with the second's projection. The scene renderer now keeps a resource set per render call within a frame.

### Missing 3D features

Sky lighting is an approximation (SH9 diffuse, mip-blurred reflections), off by default. Shadow edges are the same width everywhere, no more than 8 shadow-casting lights at a time, no occlusion culling, and bloom is the only post effect (it works in 16-bit linear light on a multisampled scene, tone mapped at the end). Skinned meshes are limited to 512 joints. Morph targets are blended on the GPU up to 16 shapes at a time, past that on the CPU.

### Physics limits

1. Tall stacks: 10 velocity iterations hold ten boxes, 20 hold fifteen; twenty need more, or substeps. A block solver or substepping (as in Box2D v3) would do better.
2. The view's lines are a texture, so they blur when seen very close and thin out on long thin triangles; there is no line primitive in the renderer. Contact and joint marks are drawn with depth testing, so a contact inside a body's mesh is hidden.
3. No continuous collision for spinning bodies, and one thread.
4. Restitution: a speculative bounce is moved to the surface by the position pass, which is exact for one point and an approximation for a face landing at an angle.
5. Hull against hull tests every pair of edge directions with exact projections: fine for hulls of a few dozen corners, slow for hundreds. Gauss-map pruning and a support-mapping (GJK/EPA) path would scale better.
6. Mesh corners are joined only at exactly equal positions; nearly touching pieces keep real edges along the gap. Seams are judged from the triangles' front sides, so a box sliding on the back of a convex fold can still catch.
7. Meshes are static or kinematic only, so a mesh is never tested against another mesh or a plane.
8. The rows of ball joints, hinges, sliders and fixed joints (pivot, axis, weld, stops and motors) are solved exactly per tree (`JointTree`, a block LDL over the joints taken leaf first: no fill-in, so time grows with the joint count; positions are fixed with the bodies weighted equally and turns capped). A stop and a motor on one axis are one row whose impulse follows its speed in steps, found by an active set that starts from last step's and re-solves when one is hit or let go; a hinge stop or motor holds a 400 kg load on a 0.2 kg arm. A chain holds its length under an end load up to 600:1 in one step, 2000:1 with 2 substeps and 10000:1 with 4. What stays a pass at a time (Gauss-Seidel with the contacts): joints closing a loop of bodies, ropes and springs. A violent whip with stops and a motor takes about twice the time of one without. A small ball with joints far from it (a bead on strings) can still fail outright.
9. The character is upright along +Y, keeps facing the same way on a turning platform, and isn't pushed by bodies that hit it (knock-backs are up to the game, through `setVelocity`). Steps are found by lifting, so a ceiling lower than the step height above a step stops it.

### `Background3D` specifics

1. Run on OpenGL only on Windows, where `Background3DDemo` started and ran without errors on both APIs. On macOS the engine's GL path is unreachable (asking for it is now a fatal error), so only the shared `Viewport3D` code was GL-tested there, through the harness.
2. Input is game input, so a UI container that has a click listener, or a draggable or scrollable element under the mouse, takes the event and the background does not see it. Give a full-window root container no listener.
3. `pointerMoved` fires while the mouse is over UI too. `pointerExited` means the mouse left the window; `charTyped` is text no UI element took (the new `Input.getTypedText()`), and `focusChanged` follows the OS focus while no element holds the keyboard.
4. It is a `Background`, so in principle it can be set on an `Element` too (3D behind one panel). That is untested, and its input assumes the area is the window.

### Project-level

1. `skiko.version` is the official 0.154.0, the first release with Vulkan, from the Compose dev repository. Its Windows x64 runtime works on both APIs; Linux and arm64 builds were not tried.
2. The Vulkan UI path and the 3D layer have run on two machines: an Apple M5 (MoltenVK) and a Windows 11 PC with an RTX 4090 (native Vulkan and native OpenGL). Linux is untested, and so are non-NVIDIA drivers.
3. The GPU tests need a window, so on a headless build machine they skip. Nothing here has been run on CI.
